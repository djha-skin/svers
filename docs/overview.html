svers is a Common Lisp library for version comparison. It supports multiple version comparison schemes.

This document is available as a PDF document.

How It Works

The key insight: by using the Debian version comparison algorithm under the hood and simply normalizing version numbers from other schemes so that they compare correctly, (almost) all of the version comparison algorithms can be improved by optimizing just the Debian version comparison algorithm.

Svers (ess-verz) is a Common Lisp library port of the Serovers library, originally written in Clojure. It supports dsolv, the Common Lisp package resolver.

This architecture also makes it easy to add and maintain new version comparison algorithms — just write a normalization function.

Svers is liberal in what it accepts. If you compare two versions using semver-vercmp but one is not semver-compliant, Svers will do its best instead of failing. This is important because package version numbers are set by maintainers, and it would be bad to break a build over a technicality.

Usage

(asdf:load-system "com.djhaskin.svers")
(use-package :com.djhaskin.svers)

;; Debian version comparison
(debian-vercmp "1.2.3~rc1" "1.2.3")  ;; => -1 (rc1 < release)

;; Maven
(maven-vercmp "1.0.0-alpha" "1.0.0-beta")  ;; => -1

;; RPM
(rpm-vercmp "1.0010" "1.9")  ;; => 1 (1.0010 > 1.9)

;; SemVer
(semver-vercmp "1.0.0-alpha" "1.0.0")  ;; => -1

;; RubyGem
(rubygem-vercmp "1.0.a10" "1.0.a9")  ;; => 1

;; Python (PEP 440)
(python-vercmp "1.0a1" "1.0b1")  ;; => -1 (alpha < beta)

;; Naive (punctuation-separated parts)
(naive-vercmp "1.2.0" "1.2")  ;; => 1

All comparison functions return:

  • Negative if the first argument is older/less than the second
  • Zero if they are equal
  • Positive if the first argument is newer/greater than the second

Version Schemes

Debian

Full epoch and revision support per the Debian Policy Manual.

(debian-vercmp "1:2.0-1" "1:1.9-2")  ;; => 1 (epoch 1 same, 2.0 > 1.9)
(debian-vercmp "1.2.3~rc1" "1.2.3")  ;; => -1 (rc1 < release)
(debian-vercmp "1.2.3-1" "1.2.3-2")  ;; => -1 (revision 1 < 2)

Maven

Supports qualifiers: alpha, beta, milestone, rc, snapshot, ga, final, stable.

(maven-vercmp "1.0.0-alpha" "1.0.0-beta")       ;; => -1
(maven-vercmp "1.0.0-rc1" "1.0.0")              ;; => -1
(maven-vercmp "1.0.0-snapshot" "1.0.0-alpha")   ;; => -1
(maven-vercmp "1.0.0" "1.0.0-ga")               ;; => 0 (ga = release)

RPM

Fedora/RPM version comparison.

(rpm-vercmp "1.0010" "1.9")    ;; => 1 (1.0010 > 1.9)
(rpm-vercmp "2.0.1" "2.0.1a")  ;; => 1 (numeric > alpha)

SemVer 2.0

SemVer 2.0 support, including build metadata ignoring and prerelease ordering.

(semver-vercmp "1.0.0-alpha" "1.0.0")      ;; => -1
(semver-vercmp "1.0.0+build1" "1.0.0")     ;; => 0 (build metadata ignored)
(semver-vercmp "1.0.0-alpha" "1.0.0-beta")  ;; => -1

RubyGem

Ruby gem version comparison.

(rubygem-vercmp "1.0.a10" "1.0.a9")  ;; => 1
(rubygem-vercmp "1.0.0" "1.0.0.a")   ;; => -1 (prerelease)

Python / PEP 440

Full PEP 440 support, including local versions.

(python-vercmp "1.0a1" "1.0b1")          ;; => -1 (alpha < beta)
(python-vercmp "1.0" "1.0+local")        ;; => -1 (local version newer)
(python-vercmp "1.0+local1" "1.0+local2") ;; => -1
(python-vercmp "1.0.dev1" "1.0a1")       ;; => -1 (dev < alpha)

Naive

Punctuation-separated parts comparison. This is the old rpmvercmp algorithm, used for Python local version parts.

(naive-vercmp "1.2.0" "1.2")    ;; => 1
(naive-vercmp "1.2.a" "1.2.b")  ;; => -1
